# r35j: SpringBoard breakpoint return addresses

Host-only diagnostic on `diag/r35g-ux-exception`, based on `622a06b`.
No base-source, firmware, device or main-branch change.

The existing X1 Mach exception tuple and saved user PC remain. For an exact
`p_comm == "SpringBoard"` and `EXC_BREAKPOINT` match, capture up to three
64-bit frame records from the exception target's saved x29. Each read copies
the pair `[fp, fp+8]` through XNU `copyin` on the referenced target map;
kernel pmaps are excluded because `copyin` can copy directly in them.
Skip missing or non-64-bit state and disabled interrupts. Enforce 16-byte
alignment and strictly increasing frame pointers; `copyin` enforces map bounds.
On a bad link or failed copy, keep the already read prefix; a missing first LR is printed
as `UNKNOWN`. Zero LR terminates the walk without recording a frame. Restore
the caller's map if switched and release the target reference before the
existing ring try-lock is attempted.

The reused source is Apple XNU `1b191cb5` (8796.141.3, APSL 2.0):
`osfmk/kern/backtrace.c` for the referenced user-map/backtrace pattern and
PAC stripping, and `osfmk/arm64/copyio.c` for `copyin` itself. No authentication
or identity is inferred from a process name or user-controlled frame data.

X1 stays on row 6, EX1–EX4 on rows 2–5. X1 prints only frame 0;
frames 1–2, when read, remain in the four-entry exception ring. For an
overwide tuple, `cs24=` prints the low 24 bits of code/subcode; the ring
still contains both full fields. Other exceptions keep the old format.
The LR is a saved return address, not the call instruction's address. If
the supplied `0x1c586c5d0` and `0x1c586c78c` are ARM64 `bl` sites and one of
them directly produced the sampled LR, the expected LR low 12 bits are
`5d4` and `790`. Frame 0 could be inside an intervening call or inherited
from an earlier frame. X1/EX PID equality is correlation, not event identity.

**Gate: deep_reviewer required before device use.** Review the exception
context, target map lifetime and fault/sleep behavior on the delivery path.
The loop bounds read attempts, not page-fault latency. The host fixture
does not execute XNU VM, and no physical scanout was measured.
Authentication remains NOT REACHED.

## Host results (self-checked)

The compiled C fixture exercised a valid chain longer than three frames,
misalignment, a self-link, and unreadable initial and subsequent frames. It
also checked the exact name/type gates, map restoration on copy failure,
kernel-map exclusion, and both example return addresses on X1. Actual X1
strings measured 57 columns normally and 80 at the formatter's conservative
integer maximum (1440 px at 18 px/cell). The EX render block is byte-identical.
Full kernel disassembly shows three 16-byte `copyin` calls gated on frame
alignment, with map restore and reference release before ring publication.

Full and compact linked audits place the sole recorder call at
`0xfffffff00779e684`; the compact IRQ guard audit and strict package linked
audit passed. The same-source compact audit preserved 49,616 non-debug
symbols and 52,674 prelink bindings; all 49,616 final non-STAB tuples matched.
The packager recomputed CHMH for the compact kernel; the outer audit extracted
the same compact kernel and a byte-identical FAT. FAT scan, FSInfo and
`fsck.fat -vn` each reported 12,054,016 free bytes (floor: 8,388,608).

Artifacts are under `UniXNU-nuwa/out/nuwa-r35j-lr-{full,compact,package}-r2-20261121`;

## Reproduction

From this worktree in WSL Ubuntu-22.04 as root, use fresh output paths:

```sh
set -e
O=$(realpath ../UniXNU-nuwa/out)
PY=/home/wh1stl3/.local/bin/python3.11
export PATH=$(dirname "$PY"):$PATH
F=$O/nuwa-r35j-lr-verifier-full
C=$O/nuwa-r35j-lr-verifier-compact
P=$O/nuwa-r35j-lr-verifier-package
A=$O/nuwa-r35j-lr-verifier-audit
"$PY" -B scripts/test-r35j-ux-lr.py "$O/nuwa-r35i-full-r2-20261121"
"$PY" -B scripts/build-r35b-kernel.py "$O/nuwa-r35-20261119" "$F" \
    --detail --exception --layout-r35h --springboard-lr
"$PY" -B scripts/build-r35b-kernel.py "$O/nuwa-r35-20261119" "$C" \
    --detail --exception --layout-r35h --springboard-lr --compact --audit-against "$F"
"$PY" -B scripts/test-r35g-ux-linked.py "$F/kernel.macho"
"$PY" -B scripts/test-r35g-ux-linked.py "$C/kernel.macho"
"$PY" -B scripts/test-r35e-irqguard-linked.py "$C/kernel.macho"
export NUWA_DETAIL_BUILD=$C NUWA_DETAIL_KERNEL=$C/kernel.macho NUWA_DETAIL_REFERENCE=$F/kernel.macho
export NUWA_LAYOUT_R35H=1
export NUWA_DETAIL_SHA=$(sha256sum "$NUWA_DETAIL_KERNEL" | cut -d ' ' -f 1)
export NUWA_DETAIL_BYTES=$(stat -c %s "$NUWA_DETAIL_KERNEL")
"$PY" -B scripts/build-ufs-apfs-root-chmh-r35i.py --output "$P"
"$PY" -B scripts/build-ufs-apfs-root-chmh-r35i.py --output "$A" --audit "$P"
"$PY" -B scripts/test-r35b-compact-package.py "$P" "$A"
```

Run the device record check from the read-only UniXNU checkout as in the
r35g instructions, with `--base origin/diag/r35g-ux-exception`.
