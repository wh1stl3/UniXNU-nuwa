# nuwa SB0 explicit write experiment — 2026-11-27

**The manual-menu outer below supersedes the original auto-boot WX outer.**
Do not use the original outer as a device candidate.

Host only and **self-checked**. No launch, device command or device write.
`--sb0-profile WX` (`NUWA_SB0_PROFILE=3`) is the *only* new compile target
that includes a reachable write. Selecting this particular kernel to run
selects the experiment; it is not gated by a button, console token or
runtime permission bootarg. The retained `native-ufs-root=1` selector is
used to reach the service entry, not to grant a write. Old unbound W is
not the delivery. The paired R r4 was neither changed nor rebuilt.
Normal resume/provider sources and the earlier no-grant EFI probe are untouched.

## Scope and terminal result

1. The existing bootstrap once-claim runs before retained host setup.
   The dedicated service opens no normal root, store, raw partitions or
   RamBlock media. SHA-256 checks the loader's exact packed seed. After
   retained setup, require RC10 LU0/4K/capacity 61,850,624, both GPT copies
   with pinned identities and matching tables, exact placement, all 770
   metadata pages zero, and the zero remote legacy anchor at `59491258`.
2. Under the retained host lock, accept one transfer admission and move
   `BootWriteOnce` from `Fresh` to `Prepared`. The real encoder stages one
   `WRITE(10)`, FUA bit clear, CDB count 1, LU0 absolute LBA `57393401`;
   the page equals the unmodified generator's `NUWAXSB3` `commit-sb0.bin`
   SHA-256 `b227e878961df9b0d30ccdd73663206e396d3d2a0466141377439d11f74a86f5`.
   After cache publication: check ownership and descriptor bytes
   (UTRD, UPIU/LUN/tag, entire CDB, PRD, length, and all 4 KiB), recheck
   actual retained queue/domain status, then consume `Prepared → Spent`
   before the one `UTRLDBR=1` store. A false result branches away from DB0.
3. Bad, busy, nonempty, already spent or invalid preflight yields zero
   **write** doorbells. An attributed full GOOD completion reports
   `GOOD-NON-DURABLE`; any write DB0 without full verified completion is
   `UNKNOWN-NO-RETRY`. Both quarantine and retain the same transport.
   The marker uses the prior translated-framebuffer row to show
   `NUWA SB0-W EXPERIMENT`, result, write count, LBA and pages (numeric
   fields hex); then masks interrupts and parks in `wfe`. No root
   return, panic/reboot call, automatic retry, FUA or flush in this path.
   Actual panel visibility and watchdog behavior have not been tested.

The lock and guards serialize this software route; they do **not** prove
firmware/old DMA revocation, SMMU exclusivity or absence of an independent
producer. Same inherited residual as the exact r4
[firmware producer census](nuwa-sb0-r4-input-20261126.md#old-firmware-ufs-producers).
There is no device-side cross-reset attempt ledger. After any attempted W
boot, especially with no terminal record or `UNKNOWN`, the operator must
choose R, not W. A blank R under that circumstance is not permission to
re-attempt. R proves observed bytes, not power-loss durability.

## Reproduce and inspect

Use the pinned host inputs and the prior [reproduction](nuwa-sb0-wr-20261126.md#reproduction);
no need to rebuild R. From this worktree in WSL:

```sh
# One fresh build+package; -verifier is a new local output suffix.
bash out/run-sb0.sh WX -verifier
# Check the exact deliverable, using a fresh audit directory.
SB0_AUDIT_OUT=out/WX-audit-verifier bash out/check-sb0.sh WX
bash out/check-wx-extraction.sh out/WX-fat-verifier
python3 -B tests/test-nuwa-crashcap.py out/WX-build/kernel.macho
```

The build and package ran with exit 0. The final combined fixture/audit,
outer FAT parse, direct FAT `mcopy` and `cmp`, read-only fsck and crashcap
ran with exit 0. The 22
ASan/UBSan fixture cases exercised the same state machine and staged
command body: exact GOOD with one write DB0, timeout/attribution faults
with one DB0 and no retry, and 19 refusal cases including busy at the
last guard, bad GPT, nonzero metadata/anchor, changed LUN/FUA/count/LBA,
bad PRD and altered payload. The first audit expected an inlined
preflight and exited 1; only the test's call-chain matcher changed.

Final ARM64 evidence is in `out/WX-audit-final/WX-final-disasm.txt`.
`sb0Run → sb0Preflight → sb0Submit → CombinedRead::issue` contains H2D
UTRD `0x12000000` and `write10` followed by a zero store to the FUA byte.
`issue` calls `sb0Consume` at `0xfffffff0079a8df4`, branches to refusal
on false, and calls hardware `hwrite(0x58, 1)` at `0xfffffff0079a8e1c`
on the admitted branch. The terminal function `0xfffffff0079a9e00`
calls the marker and loops in `wfe`. Independent deep review and verifier
pending; no hardware claim.

## Manual-menu outer (deep-review follow-up)

`out/WX-package-manual/vendor_boot.img`, SHA-256
`7f1f3c3d097e3e187030a24e66d136750a2a024c3abad59a3b857eafbefa4986`.
Only `EFI/UniXNU/unixnu.toml` differs from the original WX outer at the
file level; outer header/tail, kernel, ADT, CHMH, seed and args are unchanged.
Neither W nor R was rebuilt. Default and entry zero are `shutdown`.
After 10 seconds unattended (also the no-input fallback), the loader
selects Power off. The 60-second highlight rotation cannot start before
that timeout. Entry 2 is W and requires its own confirmation: this is
boot selection, not a new runtime write grant or a cross-reset ledger.

The r4 `UniXNU.efi` was extracted from the fixed firmware, SHA-256
`8dc2d4d755d3dd603d7232b01a410eb83095346cf3f8fd3e9f41757e8ec11c2f`.
`Config.c` resolves the default (with entry-zero fallback); `Menu.c`
returns the default on countdown expiry, `Main.c` gates confirmed entries,
and `Boot.c` issues `ResetSystem(EfiResetShutdown)` for the shutdown action.
The host regression runs that exact EFI binary, with config taken from the
final outer. It substitutes an EFI stub for W dispatch only; the VM boot
disk is read-only and contains no WX kernel or writable storage. Idle and
cancel cases ran no stub; explicit confirmation followed by cold reset or
UEFI watchdog each ran it exactly once, reset once, and then shut down with
no more input and no second stub launch. QEMU and the test script exited 0.
Evidence: `out/WX-menu-qemu/audit.json` and per-case serial/QMP logs.
This tests menu re-entry after reset, not nuwa's physical watchdog or its
boot routing before r4 starts. It does not stop deliberate reselection of W.

read-only observation. To return to ordinary UniXNU after R, externally
