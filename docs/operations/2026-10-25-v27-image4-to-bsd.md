## nonce/manifest的实际来源和边界

新生产器scripts/nuwa_launch_context.py在封装前执行，不使用其他机型常量摘要，不从nuwa fuses编造值：

1. 先读取实际新内核、固定FD、shim和基础ADT，记录其字节数与SHA256。基础ADT仍由make-nuwa-adt.py以既有批准值生成，其新random-seed不作为nonce复用。
2. Python secrets.token_bytes(32)向主机OS CSPRNG取得独立新nonce，原像只在out/image4-mainline-v27/launch/nonce.bin，报告与Git不含原像。BNCH是该原像的SHA-384，验证实际重算；并非随机生成一个摘要占位。
3. 规范JSON清单域为Nuwa.DiagnosticLaunch.v1，包含四项组件测量、nonce hash、候选生命周期及禁止混配策略。boot-manifest-hash是这份实际清单逐字节的SHA-384。清单嵌入nuwa-launch-manifest，另有明确domain标签。
4. /chosen/mix-n-match-prevention-status是32位LE1，表示本诊断平台禁止混配。/chosen/manifest-properties/BNCH为48字节nonce hash，boot-manifest-hash为48字节清单hash。空属性或允许混配值不作为默认值。

**这是主机生产的、无签名的非Apple诊断启动测量清单，不是Apple IM4M/TSS票据或硬件可信前级manifest。** nonce按候选包存续，重启同包不会重新生成，不提供持久化或硬件防重放。这些事实同时写进清单、包报告和验证结果。没有将*_verified置true，没有改认证成功结果、绕过MAC或伪造Apple可信链；后续Apple认证仍可按原逻辑拒绝不匹配对象。

验证按最终ADT剥除恰好本轮新增字段，恢复基础ADT投影并重算其摘要，随后核对实际FD/shim/kernel；错误nonce原像、BNCH尺寸、清单篡改、hash错配、策略放宽和板值篡改均拒绝。打包器新增--adt以复用已经测试的准确字节；回读实际镜像中的FD/shim/kernel/ADT再次核对，避免重新生成随机输入后封错摘要。旧包18继续可验证。

## 原生入口复核及v26纠正

v26的强制缓存切片把x19设为pmap runtime。这能证明dtless缓存不表达AMNM，但**不能证明真实Image4初始化只补合法AMNM仍在同一位置失败**。本轮从0xfffffff0046e98cc原生prologue完整执行至RET，实际x19从runtime+0x58加载，值为Darwin IOKit runtime 0xfffffff005cb14d8；原初始化的AMNM/CHMH均经它读取。

完整入口对照：原ADT到AMNM panic；仅补合法AMNM到BNCH panic；实际新测量输入使未改的原初始化也能RET。修正D-047的完整路线首因排序，原D-046缺属性事实继续成立。原生函数运行包含真实pmap数据存储取得、chip选择、缓存实例化、SecureDT、锁初始化与函数返回；IORegistry/OSData对象边界和Darwin日志为显式模型夹具，不是完整内核连续模拟或实机对象快照。

dtless在初始化后的公开AMNM/CHMH查询仍会因描述符缺失返回2，本轮将其分别交原生Darwin bool/digest getter。仅在这两个标识符且缓存已选择时改路由，其他缓存与原SecureDT后备不变。两处4字节donor分支变化显式列在build.json的image4_compatibility；不再声称donor整段未变。没有更改校验、策略值或失败返回。缺失/超长/类型错误的CHMH仍为2/84/96且输出哨兵保留。
