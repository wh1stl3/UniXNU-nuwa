## W and R

- Fixed LU0 absolute LBA `57393401`, one 4096-byte `NUWAXSB3` page, full SHA-256
  `b227e878961df9b0d30ccdd73663206e396d3d2a0466141377439d11f74a86f5`.
  The build consumes the unchanged `scripts/make-nuwa-disposable-data-init.cpp`
  generator's exact `commit-sb0.bin`, not the old `NUWADSB3` fixture data.
- Both kernels use the old root selector only to reach the retained service.
  The specialized `start` enters diagnostics instead of starting a root
  publisher, after the original single-entry claim. NativeUfsBlock and
  RamBlock refuse start; store and raw
  partition entries return failure; log/export were already disabled.
  The diagnostic neither publishes a device nor returns to normal boot.
  Linux/EFI recovery alternatives and normal resume are unchanged.
- Before media inspection, hash the exact packed boot seed in the loader
  memory-map (2,744,480 B, `3c81135b…`); the outer audit independently checks
  its decoded 8 GiB seed and `SHNGSEED2` logical identity. Use the unchanged
  retained bring-up (NOP, status query, conditional wake, TUR, RC10 and its
  initial LBA0 read). Then require capacity 61,850,624 and 4K; validate
  both GPT copies' CRCs, identities, reciprocal
  LBAs, table agreement, bounds, and exact disposable placement. The backup
  array pointer is bounded before it is followed; the historical captured
  layout has it at `61850619`, not `capacity-2`. No live root/image
  verification is claimed.
- **W — unbound:** require 770 zero pages plus the zero remote legacy anchor
  at `59491258`. The device image has no grant source: it stops with
  `NUWA SB0-W UNBOUND AUTH-UNBOUND`, before write staging. The separate host
  arm exercises the same staged `CombinedRead` and comparison of actual
  UTRD, UPIU/CDB, one PRD and 4096 data bytes after the normal transport
  guard and before DB0. It consumes the mock claim there, issues one
  non-FUA WRITE(10), and cannot replay after GOOD or an unknown result.
  The real image does not contain the host arm. GOOD proves command
  completion only, not persistence.
- **R — independent read:** reads all 770 pages for a content verdict; a
  transfer failure terminates immediately. `NUWA SB0-R READONLY` plus
  `BLANK`, `EXACT-SB0`, `MISMATCH`, or `IO-FAIL` identifies the profile and
  classification; evidence also includes the target and offending LBA,
  pages, total submitted commands, and zero writes. Seed, geometry and GPT
  have separate refusal labels. Exact means every byte in SB0 matches and
  all 769 remaining pages are zero. R does not read the remote legacy anchor.
- Both profiles retain/quarantine the DMA session when done. Current
  producer exclusion is a **static** property of the specialized nuwa
  driver paths; old firmware/DMA producer revocation and exact isolated
  runtime entry/result delivery have not been established. A genuine W
  binding must supply an independently authorized one-shot claim that
  cannot be reused after an ambiguous result/reboot, with target/seed and
  attempt identity, and must prove the exclusive device session. No
  bootarg or ADT value acts as that grant. Independently reread with R
  before interpreting a submitted result; readback alone is not durability.

## Reproduction

`out/run-sb0.sh` records the local build/package commands; it uses fresh output
directories and the historic WSL linker and compilation records. In the
worktree under WSL, use the [crashcap build recipe](nuwa-crashcap-20261125.md#reproduction)
with the pinned disposable inputs and `--pixsig --data-persist-diag
--data-candidate-gpt <captured primary header and table with a 4096-byte
leading sector> --disposable-data --sb0-profile W --sb0-payload <commit-sb0.bin>`.
Repeat for R. In each case repackage with `scripts/package-nuwa-crashcap.py
--sb0-template <6695…vendor_boot.img> --sb0-profile W|R`, then rerun the same
command with `--audit-only`. Use `tests/test-nuwa-sb0-candidate.py W|R
<build> <fresh test output>`, and `fsck.fat -vn <package>/readback-fat.img`.
The fixture's native binary uses ASan and UBSan; the final audit targets
the linked Mach-O rather than a model. No test uses a device.
