# DarwinBoot 4.75 GiB window — host candidate

`board.toml` changes the owned window from `0x40000000` (1 GiB) to
`0x130000000` (4.75 GiB, 5,100,273,664 bytes, 2 MiB aligned).
The 12 GiB device capacity is confirmed by the user and recorded live FDT
`ddr_size=0xc`; the earlier 8 GiB statement is superseded. The choice is
approximately 39.6% of 12 GiB and, as reported by the user, matches sheng's
12 GiB device selection.

If a later authorised boot reports NO WINDOW, allocation failure, or stalls
at entry, fall back first to 3 GiB (`0xC0000000`); on the same failure,
fall back to 2 GiB (`0x80000000`). Each value requires a newly generated
and audited payload. No device action is authorised by this host change.

Boot-chain and page-table effects require `deep_reviewer` review. Firmware
allocation, boot, and independent verifier rerun remain unverified.

## Host self-check

than rerunning the general ADT generator. Its new explicit `--board-window`
mode replaces only the existing unique u64 window with the board value;
the previous CHMH, root, ADT equality, FAT and outer checks remain active.
This is a derived ADT, not a claim that the official payload step was rerun.

value bytes at `0x23e8`: `00 00 00 30 01 00 00 00` (LE
`0x0000000130000000`). ADT SHA-256:
