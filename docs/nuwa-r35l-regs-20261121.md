# r35l: SpringBoard saved-register snapshot

This host-only overlay on diagnostic branch base `e25a4dc` uses the pinned r35h
renderer and r35g exception tap (the exact source pair in the r35i full
artifact). It does not change the UniXNU checkout or the older r35 variants.

The tap writes one ring entry per matching event: exact `SpringBoard` process
name, `EXC_BREAKPOINT`, and saved `PC & 0xfff == 0xca8`. No record is made
without a 64-bit saved state. PC and x0/x1/x2/x19/x20/x21/x22 come from that
same kernel saved state. The tap does not read through register pointers,
read the user stack, call `copyin`, or switch maps. The existing try-lock can
drop a matching event; no other exception displaces the latest matching one.

X1 keeps `pid/t/c/s/pc`. X2 prints x0/x19/x20 and X3 prints x1/x2/x21/x22 in
the displayed index order. All seven values are fixed-width 16-digit hex.
The register rows override the stage/AKS and IRQ summaries on rows 7–8 when
a snapshot exists, keeping both rows inside the modeled panic-safe band. EX1–EX4
are unchanged and remain a separate exit history. The last 12 bits of the PC
are a filter, not proof of image identity: correlate the full PC and PID.
The experiment distinguishes zero, small integer and pointer-shaped x0 values;
a pointer-shaped value does not prove the pointer is valid. No displayed
snapshot is inconclusive (not reached, no matching state, a try-lock drop,
or no refresh after the write).

## Host results (self-checked)

The generated C replay measured 79/64/80 columns for X1/X2/X3 and compared
EX1–EX4 with the pinned source byte for byte. The previous r35g and r35k
host fixtures also passed unchanged. The full and compact linked audits
each found the sole `handle_ux_exception` → `boot_progress_exception`
edge at `0xfffffff00779e4e0`; the recorder is a leaf, and neither symbol
directly calls user-copy, map or backtrace routines. The IRQ guard audit
also passed on compact. The native debug-strip audit preserved 49,614
non-debug symbols and 52,674 prelink bindings. UniXNU remained pinned at
`693f5d9c`; read-only upstream HEAD checks both returned `8542980d`.
The separate outer audit extracted a FAT and kernel with the same digests
as the packaged FAT and compact kernel. Strict linked audit: ALL PASS;
49,614 final non-STAB symbol tuples matched. The FAT scan, FSInfo and
`fsck.fat` agreed on 12,070,400 bytes free (11.51 MiB), above 8,388,608 bytes.

## Independent verifier rerun

Run from this worktree in WSL Ubuntu-22.04 as root, with fresh output paths:

```sh
set -e
O=$(realpath ../UniXNU-nuwa/out)
PY=/home/wh1stl3/.local/bin/python3.11
export PATH=$(dirname "$PY"):$PATH
F=$O/nuwa-r35l-verifier-full
C=$O/nuwa-r35l-verifier-compact
P=$O/nuwa-r35l-verifier-package
A=$O/nuwa-r35l-verifier-audit
"$PY" -B scripts/test-r35l-ux-regs.py "$O/nuwa-r35i-full-r2-20261121"
"$PY" -B scripts/build-r35b-kernel.py "$O/nuwa-r35-20261119" "$F" --detail --exception --layout-r35h --springboard-regs-r35l
"$PY" -B scripts/build-r35b-kernel.py "$O/nuwa-r35-20261119" "$C" --detail --exception --layout-r35h --springboard-regs-r35l --compact --audit-against "$F"
for D in "$F" "$C"; do
    "$PY" -B scripts/test-r35g-ux-linked.py "$D/kernel.macho"
    "$PY" -B scripts/test-r35k-regs-linked.py "$D/kernel.macho"
done
"$PY" -B scripts/test-r35e-irqguard-linked.py "$C/kernel.macho"
export NUWA_DETAIL_BUILD=$C NUWA_DETAIL_KERNEL=$C/kernel.macho NUWA_DETAIL_REFERENCE=$F/kernel.macho NUWA_LAYOUT_R35H=1
export NUWA_DETAIL_SHA=$(sha256sum "$NUWA_DETAIL_KERNEL" | cut -d ' ' -f 1)
export NUWA_DETAIL_BYTES=$(stat -c %s "$NUWA_DETAIL_KERNEL")
"$PY" -B scripts/build-ufs-apfs-root-chmh-r35i.py --output "$P" </dev/null
"$PY" -B scripts/build-ufs-apfs-root-chmh-r35i.py --output "$A" --audit "$P" </dev/null
"$PY" -B scripts/test-r35b-compact-package.py "$P" "$A"
```

From UniXNU, rerun the record check as in
[r35g](nuwa-r35g-ux-exception-20261121.md#reproduction), with
`--base origin/diag/r35g-ux-exception`, and run `git diff --check` in the
device worktree.
