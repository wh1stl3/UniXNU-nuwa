# Display client entry probe — host candidate

The CPU-only staged source preserves the override in
`UniXNU/drivers/GopFramebuffer/NativeLegacyDisplay.cpp:857–860`: entry is
called with task and type before the parent's four-argument `newUserClient`,
and observed with the full IOReturn after that call returns. The existing
compiled CPU-only `NativeLegacyDisplay.o` contains the override and undefined
references to both callbacks. In the new build its disassembly has `bl`
relocations at object offsets `0x7c8` and `0x804`, and the final kernel
defines both callback and counter symbols. This establishes compiled call sites, not that
runtime dispatch or either callback actually happens on a device.

The two independent 64-bit atomics pack a wrapping 32-bit count above a 32-bit
value. Compare-exchange allows multiple callback writers: `in/lastin` are
entry count and latest entry type; `out/ret` are completion count and latest
completed parent return. Latest means successful atomic update order. Each pair
is coherent, but the two pairs are independently sampled and need not describe
the same request or instant. No enter/observed pairing is claimed.

Row 9 appends `CLI in=<n> out=<m> ret=<hex32> lastin=<hex32>` to DSP; the
full-width type is shown, rather than truncating it. Missing weak symbols
display `CLI unavailable`. EX1–EX4, X1–X3, FDR and conditional stg are not
replaced. This row may be unavailable during panic or after scanout handoff.

* `in=0`: no entry observed (also possible after 32-bit counter wrap); this
  does not establish why, or prove a matching/discovery failure.
* `in>0, out=0`: an entry was observed, but no completion was observed
  (subject to count wrap and independently sampled values).
* `out>0, ret=00000000`: the recorded parent `newUserClient` returned success.
  It does not establish final userspace open success; IOUserClient processing
  can reject later.
* `out>0, ret!=0`: the recorded parent return was nonzero. This is not proof
  that the outer IOServiceOpen ultimately failed: the five-argument service
  path can fall back after the four-argument call.

Host-only; reviewer re-review of atomic updates and display layout, plus
deep_reviewer review of concurrency changes, are required. Runtime, independent
verifier and authentication remain unverified; no device action authorized.
