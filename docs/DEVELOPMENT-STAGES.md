# nuwa各阶段开发方法与执行规则

用户2026-10-27要求：官网作为开发指南，且每阶段的具体方法和步骤落为规则。本文件由两仓AGENTS明确引用，是后续任务必须执行的本地方法约定，不只是建议清单。适用于D:/Code/PortingiOS/nuwa/UniXNU-nuwa与D:/Code/PortingiOS/nuwa/uefi-nuwa；具体当前状态只以STATUS及最新交接为准。

官网提供依赖/接口方向，以下步骤结合nuwa既有约束具体化。S00—S13为本仓工作编号，不是官网阶段编号，也不是通过记录。用户明确指令与既有硬停、只读、隐私、串行和不提交约定优先；本文件不新增逐步审批或自动发布授权。离线指不用实机，仍须查公开资料。

## 通用执行方法：每个开发任务均须执行

1. **定位问题。** 先读AGENTS、STATUS与最新交接，选择下表阶段；明确目标、已有证据、缺失前提、完成条件。简短写入当前操作记录或现有报告即可，不为每次读文件另造流程表。
2. **固定输入。** 查对应官方章节和原始实现，记录访问日期、仓库/提交、文件摘要、许可、硬件/OS范围；同一任务已固定的材料可复用，出现变化先比较差异。用nuwa实际文件和实测约束参考实现，未知参数写TODO。
3. **追踪真实路径。** 按输入→入口/调用者→状态/资源→完成/错误→释放追踪。检查实际编译、链接、初始化和匹配路径；不把配置项、注释、函数存在或第三方设备记录当运行结果。
4. **形成连贯改动。** 在已有授权范围自主实施有依据的修复和依赖，不为每个成功点停下。可一次覆盖多个能从代码确定的项目；保留原生错误、认证与恢复路径，不用空实现、假成功、猜测锁/IRQ/缓存参数填补未知。
5. **验证改动。** 先执行与变化有关的静态、编译/链接、解析边界或模拟差分检查。二进制观察须核对原始指令、寄存器/标志/原生内存和控制流；必要时用负对照证明检查能拒绝真实错误。检查通过后只在有新改动、失败或未决风险时增加/重复测试，脚本/编译/模拟始终串行。
6. **完成交付。** 记录命令、输入/工具版本、来源和产物SHA、实际输出、失败与续验关系。新产物和报告使用独立路径；不能覆盖原证据或重算历史摘要冒充原验证。改启动参数/有效载荷时重建依赖的payload与boot包，并回读实际包内容。
7. **分别验收。** 源码审查、离线检查、QEMU和实机分别记录；Unicorn模拟不冒充QEMU或硬件。每轮继续实机前，执行AGENTS第8节“实机前先充分分析实际代码”：先报告最大嫌疑及代码证据、反证和剩余不确定性，明确本轮观测范围与证伪结果，再按已有授权及观测/恢复门实测；不新增逐轮审批。只在前提具备且设备工作已恢复时作必要实测。未完成项明确保留，不通过置verified或放宽断言消除。
8. **收尾与续接。** 同步STATUS、最新交接和只追加WORKLOG，写明下一可执行项。失败先归因和处理；触发已有硬停时按AGENTS登记所需审阅，权限拒绝停止对应操作。等待人工操作期间继续不依赖它的已授权离线工作。

## S00 · 硬件资料与证据

**方法与步骤：**
1. 用迁移索引确定新路径，检查两仓现有修改，保留原证据和当前工作；不创建替代仓、不操作enuma、不启动第二写入者。
2. 建立nuwa硬件事实表：CPU/SoC版本、内存及保留区、GIC/定时器、存储、显示、输入、固件。逐项标注DTS、厂商源码、固件或哪次实际观测。
3. 区分“同SoC可评估”“同板已确认”和未知；核对寄存器宽度、地址转换、单位、IRQ与固件所有权，不直接移植donor常量。
4. 固定相关领先设备的提交、实测记录与实现版本，比较相似条件和差异；追溯时使用旧路径，不向Legacy写入。

**离线验证/产物：** 来源表、摘要、矛盾与TODO、后续可实现接口清单。禁止把其它设备的stage/视频当nuwa结果。**完成标准：** 本次将用到的硬件值有来源，未知项明确隔离；不要求为资料收集重复启动设备。

来源：[总流程](https://unixnu.com/porting/steps)、[SoC支持](https://unixnu.com/porting/soc-support)。

## S01 · SoC、OS、组件和ABI契约

**方法与步骤：**
1. 固定iOS16/8796与当前IPSW身份，列出原kernelcache、头文件、用户态和工具版本；不套官网默认iPadOS17模板。
2. 对每个组件记录功能、硬件范围、依赖、OS ABI、板级回调与许可，优先选择有实际领先设备证据的兼容实现。
3. 写清接口的调用方向、参数宽度/布局、返回值、超时、回调线程、缓冲区归属和释放点。私有类须核对原输入的布局/虚表/selector，不能从不同OS复制固定地址。
4. 追踪配置片段、补丁顺序、构建脚本、archive、初始化调用者和provider属性。数组覆盖时保持完整选择，不丢继承依赖。
5. 若使用新Format2流程，先固定实际解析的profile/本地覆盖/来源和组装树；未具备迁移资格时做独立映射与核验，不改坏现有诊断链。

**离线验证/产物：** ABI/依赖契约、来源pin、实际构建/初始化图。**完成标准：** 被调用接口的身份和ABI有证据，缺口没有被stub掩盖；构建通过与硬件资格分开。

来源：[组件目录](https://unixnu.com/reference/components)、[驱动集成](https://unixnu.com/porting/drivers)。

## S02 · DTS/ADT、固件与菜单

**方法与步骤：**
1. 分清固件使用的DTB与XNU使用的ADT，检查节点/属性消费者、reg/ranges、cells、端序、宽度、IRQ/phandle和启用状态。
2. 从实际DSC/FDF与库映射追踪菜单、DarwinBoot、RAMDisk、DiskIo/FAT等所需模块。模块必须实际进入FD；配置列出不算完成。
3. 检查FDT initrd→HOB→Block I/O→文件系统→配置/菜单入口的交接与边界；不把菜单出现等同payload发现成功。
4. 在不覆盖脏树的构建路径编译，核对FD路径、容量、模块与输入摘要；重建与其关联的payload和boot包。
5. 后续实测依次记录固件输出、菜单/输入、目标入口及loader日志；固件日志导出依赖真实producer和插件。

**离线验证/产物：** 树属性检查、FD模块/依赖清单、包回读。**实机完成标准：** 目标菜单和配置入口可用，交接日志属于本次产物；缺协议时查对应模块，不扩大到猜改地址。受审内存/基址/尺寸变化先触发现有硬停。

来源：[设备树](https://unixnu.com/porting/device-tree)、[UEFI集成](https://unixnu.com/porting/uefi-firmware)。

## S03 · 内核/prelink、payload与loader

**方法与步骤：**
1. 固定source kernel、原kernelcache、组件roots、补丁/绑定和预期Mach-O/boot_args ABI，分别核对镜像身份与代码来源。
2. 检查架构、入口、segment/文件边界、装载/slide、原组件依赖、导入绑定、模块入口和初始化顺序。原始字节改动必须有逐项说明。
3. 编译并检查archive对象及启动符号，复核prelink报告与最终内核；有本轮可复现要求时独立目录重建比较，不能扩写成所有运输包均逐字节可复现。
4. 将ADT、nonce/manifest、trust输入、根镜像与实际内核绑定；检查payload和boot文件系统中的实际字节，而非只核对外部文件名。
5. 后续loader观测检查真实EL、入口、参数、几何和交接；失败先区分loader拒绝、内核入口和后续执行。保留认证错误，不伪造成功。

**离线验证/产物：** 固定输入、编译/prelink/包资格、差异和失败记录。**实机完成标准：** 捕获与该候选一致的交接及内核阶段；fastboot ACK或绿色交接条不证明用户态。

来源：[prelink](https://unixnu.com/concepts/prelink)、[启动阶段](https://unixnu.com/porting/bring-up)。

## S04 · 平台、CPU、IRQ、时钟、内存与DMA

**方法与步骤：**
1. 追踪平台匹配与子节点发布，再核对CPU affinity、PSCI、GIC版本/stride、timer频率及IRQ的实际消费者。
2. 建立固件保留区、kernel/payload、framebuffer、设备DMA缓冲区的所有权图。分别检查CPU地址、物理地址、IOVA、位宽、对齐与cache契约。
3. 明确固件状态接管还是冷初始化；核对SMMU实例/stream/context和中断确认/撤销归属，不能以bypass名义忽略位宽或共享设备。
4. 离线检查表项、边界、ABI及错误/释放路径；设计有界timer、IPI或DMA往返观测。先证明所需基本资源，再启用新增核/消费者。

**完成标准：** 对实际启用CPU有独立entry/timer/IPI结果，对设备缓冲有可达性及完成证据。内核文字或单个线程运行不代替全IRQ/SMP资格；模拟结果不证明硬件缓存/一致性。需要改受审内存字段或无来源硬件参数时按既有硬停/证据规则处理。

来源：[平台与内存](https://unixnu.com/porting/platform)。

## S05 · 块存储、文件系统、root和Data

**方法与步骤：**
1. 先区分当前RAMDisk、UFS、其它传输和根文件系统；分别定义read、mount、Data写入与持久化的完成条件。
2. UFS先确定寄存器/PHY/时钟/电源与request list/SMMU接管归属，再准备可达DMA缓冲和有界命令；依次检查控制器/响应状态、容量、已知块与GPT。
3. 逐项核对LUN、逻辑块大小、LBA到字节转换、OS/SystemOS/Data/log窗口边界和发布/匹配条件。不得照搬其它设备分区布局。
4. 文件系统从实际操作入口追到子调用、返回状态、实际字节和释放；配对记录调用/续接，区分“未观察到返回”和确定阻塞。压缩内容宿主可解码不替代内核IO/codec通过。
5. root可读/可挂载后，单独设计和核验Data、读写同步、故障/复位后的状态。任何设备写入须满足既有具体目标、日志和恢复要求；离线先用独立文件镜像验证布局。

**离线验证/产物：** 有界布局/只读读取/解析检查、已知数据摘要、文件系统调用与返回契约。**实机完成标准：** 传输、文件系统、root、Data及持久化分别有证据；RAMDisk成功不验收UFS，mount成功不验收launchd。

来源：[UFS](https://unixnu.com/porting/ufs)、[平台/OS服务](https://unixnu.com/porting/platform)。

## S06 · 完整用户态、exec、launchd和桌面服务

**方法与步骤：**
1. 分清RestoreRamDisk与完整OS，固定OS/SystemOS/AppOS、manifest及构建版本；只读重验新路径中的真实输入，不改历史报告。
2. 建立组合命名空间：挂载/overlay归属、绝对和相对链接、越根/循环、路径冲突及元数据。记录实际文件来自哪个组件，不靠物理复制后猜来源。
3. 检查dyld主/子cache引用、UUID、路径索引及桌面依赖；区分独立文件、cache成员、弱依赖和未知。头字段/文件数量不等于闭包完成。
4. 核对Mach-O装载/入口、CPU类型、页/段、dyld、签名/entitlements与原生接受条件；首次dyld执行、launchd入口和服务运行分别记录，不用摘要匹配替代认证。
5. 枚举目录plist及iOS主launch配置，核对程序、触发、用户/组、IPC依赖、文件系统/设备需求与Data所有权；逐项审阅恢复服务和桌面服务，不能整批默认放行。
6. 离线准备需要的最小完整服务链与错误路径；后续按原生读取完成→exec认证/映射→实际EL0/dyld→launchd→Data/服务→可见界面核验。

**离线验证/产物：** 可追溯输入/命名空间/cache与依赖报告、服务内容和Data计划。**实机完成标准：** 有实际用户PC/进程与服务输出，再记录桌面呈现；当前239释放门保持，完成静态审阅不是自动解除门或认证策略的授权。

来源：[启动阶段](https://unixnu.com/porting/bring-up)、[prelink/OS服务](https://unixnu.com/porting/platform)。命名空间/cache细则为nuwa结合现有输入与领先设备方法的本地规则。

## S07 · 显示、CPU呈现、刷新和亮度

**方法与步骤：**
1. 先核对并保留实际scanout分配、几何、stride和像素格式；显示控制器、面板和背光的控制/电源归属单列。
2. 核验本输入的MobileFramebuffer/IOSurface接口、类布局、请求及完成语义，追踪provider、初始化与链接。
3. 先做有界CPU帧呈现，检查源/目标范围、cache契约、swap序号、源surface寿命及超时完成/释放；再接真实刷新通知。
4. 从板级观测确定刷新和背光接口；分开记录请求帧率/实测刷新与亮度读写。先读固件状态，不能直接复制sheng控制器写入。

**完成标准：** 正确已知帧、连续更新、swap完成与资源回收，再到用户态合成帧。HEX写屏、菜单GOP或用户态库文件存在不算桌面显示通过；GPU接入排在基本呈现与DMA资格之后。

来源：[显示指南](https://unixnu.com/porting/display)。

## S08 · 触摸、按键和HID

**方法与步骤：**
1. 固定实际传感器/固件、总线、电源/复位/IRQ、几何和OS HID ABI；同SoC或DTS残留节点不能确定实际芯片。
2. 按电源/时序→总线完整传输→芯片识别→固件/协议→完整帧解码推进，每一步检查状态、长度和错误恢复；不在接收回调内无界等待。
3. 转换坐标/方向并维护接触ID、按下/移动/抬起、多点和边缘；提供一致快照和正确报告描述符，核对HID初始化/匹配/链接。
4. 实体键单独核对极性、去抖/中断确认、press/release、长按与同时按键，并验证其到OS报告的对应。

**离线验证/产物：** 协议样本、解析/边界/接触生命周期和HID契约检查。**实机完成标准：** 实际事件到达OS且界面坐标/动作正确；芯片ID、回环或模拟按键不替代真实触摸。未具备实测条件可继续解析/编译，不猜GPIO/电源值。

来源：[输入指南](https://unixnu.com/porting/input)。

## S09 · GPU和Metal

**方法与步骤：**
1. 在基本呈现和DMA前提下核对GPU代际、GMU/固件、供电/带宽、SMMU和所选OS GPU/IOSurface ABI。
2. 按供电/固件就绪→通信→ring进度→有界命令与fence→已知图像推进，分别保留失败和超时结果。
3. 再核对客户端对象/导入、映射及alias/cache类别、提交、完成和teardown；不要先用复杂桌面负载掩盖基础错误。
4. 连接匹配的用户态frontend/编译链，追踪库、插件、服务和合成器到显示swap完成的闭环，再量测UI负载与性能。

**完成标准：** 单独记录内核提交/内存、已知渲染、用户态前端及桌面呈现。A740名称相同、构建通过或CPU拷贝画面均不替代GPU资格；固件/内存/板级参数仍受既有边界约束。

来源：[GPU/Metal](https://unixnu.com/porting/gpu)。

## S10 · 网络

**方法与步骤：**
1. 确认真实芯片/总线ID、固件与校准变体，再核对供电/复位、PCIe或实际总线、BAR/传输、DMA及中断。
2. 实现组件的时间、分配、DMA同步、固件读取和事件回调，明确CPU/总线地址与线程归属；接收数据异步交付前转入OS所有权。
3. 按链路/设备识别→固件/服务启动→扫描→认证/关联→地址配置→双向流量推进，逐项检查返回和超时。
4. 接入匹配的OS网络接口/请求格式，再测断连重连、持续收发及停止/资源释放；USB日志网络、无线和系统网络UI分别验收。

**完成标准：** 固定固件/AP条件下的连接、地址、收发和恢复结果；扫描不代表联网，联网不代表密码保存或全功能。凭据不进入日志、源码或报告。

来源：[网络指南](https://unixnu.com/porting/network)。

## S11 · DSP、音频、电池、频率和平台电源

**方法与步骤：**
1. 分离传输、设备协议和OS服务，固定固件、内存、mailbox、通道、codec/放大器/量测协议及板级供电归属。
2. DSP先建立ready/crash、通道与有界消息往返，匹配请求token；接收只做有界入队，断开时取消请求，重连重新协商和订阅。
3. 音频先选一条真实播放或录音路由，检查format/拓扑、时钟/放大器和DSP映射，依次open/configure/prepare/start/stop/close，核对period完成、同步和回收；随后接OS音频服务。
4. 电池核对实际量测、单位/符号/范围与通知；频率/电源核对可用OPP、热限制、睡眠/唤醒依赖，再接OS策略。不得用固定电量或假状态冒充真实管理。

**完成标准：** 传输、实际输出/采集、数据通知和状态恢复分别有证据。非必要性能/电源功能不抢在桌面基本路径前；但被其它阶段依赖的电源资源必须先具备。

来源：[DSP、音频与电源](https://unixnu.com/porting/power)。

## S12 · 日志、恢复和自动循环

**方法与步骤：**
1. 从早期阶段确定可用观测：固件buffer/二维码，内核UART/画面；记录发生在哪个交接阶段，不默认UEFI服务在内核继续可用。
2. 设计有阶段/调用/返回/错误含义的日志，现场记录等待时长与稳定性；保留原媒体，派生图/转录单独绑定。调用前标记不是callee入口或停止PC，累计条带不代表唯一调用或完整时序。
3. 持久化前核对独立日志窗口、writer/reader格式、大小/边界、boot ID、同步及写入状态；存储和恢复资格具备后，先完成一次手动回收。
4. 自动循环只能在已完成日志回收、复位与设备授权/观测条件下启用；绑定具体设备、候选、超时与每轮目录，已消费候选不重发。
5. 每轮按当前恢复约定补设备身份、Android完成1与相关分区后验。缺日志/中间失败保留，不把USB枚举或ACK作为内核阶段证据。

**完成标准：** 可归属本轮、可解码的阶段证据和真实恢复闭环；不得未经依据占用分区/复位寄存器。当前暂停实机期间，仅做日志格式/工具和离线检查，不运行设备循环。

来源：[日志与自动测试](https://unixnu.com/porting/log-capture)。

## S13 · 集成、打包和阶段交付

**方法与步骤：**
1. 检查所选功能的来源、依赖、实际编译对象、启动/匹配和OS接口，缺前提的能力明确保留未验收，不能通过配置选择掩盖。
2. 串行完成与本次变化相称的检查/构建；失败保留，修复后在新输出续验，证据明确对应候选及源码。镜像/参数变化后重建其依赖，不只改外部描述。
3. 回读最终镜像的内核、ADT、固件、配置与sidecar，核对摘要和预期入口；独立重建比较的范围如实说明。
4. 区分“可交付的离线诊断包”“具有本阶段实测结果”“可用完整系统”；启动前单独满足身份/观测/恢复和当前用户安排。成功里程碑不中断原生主线。
5. 同步状态/交接、失败、未完成项和续接命令，过期消费命令只用于追溯；按用户现有约定不自动提交/推送/发布。将来明确授权发布时再逐项按官网仓库完成流程核对。

**完成标准：** 代码、产物、命令和证据互相绑定，当前能力/缺口可复核；不将离线资格扩写成实机或桌面完成。文档维护不要求重跑旧硬件试验。

来源：[总流程](https://unixnu.com/porting/steps)、[驱动集成](https://unixnu.com/porting/drivers)、[阶段验收](https://unixnu.com/porting/bring-up)。
