# nuwa 显示验收方案（2026-11-25）

状态：**INSUFFICIENT EVIDENCE**。本记录转述 reviewer 的方案修正，不代表客户端已经实现或验收已经执行；无设备操作。reviewer 结论摘要为 **CHANGES REQUIRED**；当前是证据缺口，不是已发现的 ABI 破坏，无需就此升级 deep_reviewer。以后若实际改动触及启动链、ABI、DMA/IOMMU 或锁并发，仍按项目路由审查。

## 官方标准

依据本地 UniXNU 基座 `693f5d9cae8a408dd18b39f3f9fdc4228c934241` 的 [`docs/zh/porting/display.md:30–56`](https://github.com/UniXNU/UniXNU/blob/693f5d9cae8a408dd18b39f3f9fdc4228c934241/docs/zh/porting/display.md#L30-L56)，整理为六项：

1. XNU 发布显示服务；选择 GopFramebuffer、显示归档及依赖，启用所需配置和初始化。
2. CPU 呈现路径确认像素布局、行跨度、分配大小和缓存处理，实际显示已知画面。
3. 呈现画面并完成交换；适用 wire 路径时以 sequence 关联提交和完成。
4. 交换完成通知与 IOSurface 生命周期闭合；交换结束前保留源帧及引用，并处理超时和失败。
5. 适配目标控制器时序读取，分别记录请求刷新率和测得帧时序。
6. 上述完成后才启用 GPU 呈现。

现有主控转述的 `co=6 ret=6` 是传输链路冒烟，其中 `co` 可能包含清屏；它们不是已知画面、生命周期、用户通知或显示端时序的证据。`bk/so/PIX` 是诊断拆分，不是验收标准。

## 验收客户端设计

- 已知图带 run ID 和递增帧号，包含四角不对称色块、白框和中央十字；保留首、中、末检查帧及预期图案，供实拍比对。
- 每请求键为 `(run ID, connection ID, swap sequence, surface ID + 创建代次)`，避免跨连接、复用 surface ID 或不同运行错配。
- 单帧在途，前一帧终态和引用条件闭合后才提交下一帧。30 Hz 仅为提交目标，不当作实测显示刷新率；独立记录显示端时序及其来源。
- 逐请求追踪 `submit → accepted → 驱动取引用 → CPU 消费 → 完成 → 用户通知`，保留各事件身份、时间和结果；不把函数返回值等同用户通知。退出先 drain 在途请求，再注销通知、释放引用；记录完整清理结果。
- 先核实 ABI、通知机制和事件可观测性；不可从拟议事件链推断已存在接口，也不猜 selector。

## 通过标准

1. 记录并核对实际显示服务实例身份及本次客户端连接身份。
2. 必须实拍首、中、末检查帧，与对应 run ID、帧号和预期图案比对，确认几何与颜色；照片、录像和截帧只保存在本地，记录结论及哈希，不入 Git。
3. 正式运行有 100 个 accepted 请求，每个请求以完整键唯一关联且恰有一个成功终态和对应用户通知；不可用提交次数或返回次数替代。
4. 生命周期异常计数全 0，包括错配、重复、超时、提前释放或源仍被使用即复用；退出 drain、通知注销和引用释放闭合。
5. 分别记录请求/提交目标和显示端实测时序，给出中位数、P95、最大值及漏周期数，说明时间源、统计窗口与漏周期计算口径；不设无依据 SLA。

## 执行顺序与止损

1. 主机核实候选内核、客户端和显示服务 ABI、通知与引用合同，并记录可用证据；未核实即停。
2. 实现验收客户端及单次 job，限定本次 run，先在主机核对记录和清理路径。
3. 单帧预检，确认服务身份、真实 surface、完整事件链与实拍图案。
4. 通过预检后执行 100 帧正式运行并保留首、中、末检查帧。
5. 主机汇总原始记录和实拍比对结果，逐项签字；本方案不授权任何设备操作，实际执行须另获当轮授权。

仅有 `bk`、图案错误、通知超时、画面被其他生产者覆盖，或出现请求错配、重复、超时、源仍使用即复用，立即停止并保留证据；不猜 selector、不把 `ret` 改名为通知、不新增全局策略绕过。

## 证据边界

实拍是通过条件；目标回读仅在图案错误时辅助定位，不能替代实拍。100 帧只签本次观察窗口，不签长期稳定。GPU 呈现后置。当前仅为 reviewer 方案转述 / self-checked 记录，ABI、客户端、设备表现和验收均尚未验证。
