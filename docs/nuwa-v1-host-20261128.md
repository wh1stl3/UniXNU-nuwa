# nuwa Data v1 直写主机候选（2026-11-28）

**主机 v1 入口确实到达非 stub 文件后端；生产内核未切换到 v1，写门仍关闭。** 主机自检，无设备访问、刷写、启动载荷或窗口改动。

实际调用链：`NativeRamBlock::attachStore` / `doAsyncReadWrite` / `StoreOps` → 上游 `DirectDisk.h` / `PersistOverlay.h` → staged `native_ufs_store_{open,read,write,sync}` → `KernelPort.inc::openCandidateData`、`Provider`、`RetainedWritePort` → staged `CombinedRead::issue` → 模拟控制器提交普通文件 I/O → retained 解析和 `Slot`。主机编译不定义 `NUWA_DATA_CANDIDATE`，由原有分支选中 v1；不替换 `StoreOps`。只有主机进程启用构建 opt-in、模拟 boot args、双 GPT 及文件域资格。轨迹的 `FUA_OK` 表示文件写及 `fdatasync` 完成、模拟返回被接受，不是设备 WRITE(10) FUA 或断电耐久证据。

来源：`UniXNU/UniXNU@693f5d9cae8a408dd18b39f3f9fdc4228c934241`（RamBlock，BSD-2-Clause-Patent）；retained C 入口取自[既有 v3 构建](nuwa-dualbank-integration-20261126.md)，staged `NativeUfs.cpp` SHA-256 `aaf67cfe336aab6ed6486be8544367910664fffabc3f7b42386ca9a26c89f84c`。共用传输取自[无字形构建](nuwa-no-glyph-examples-20261128.md) 的 staged `CombinedRead.h`（SHA-256 `1dffd6ba27c113e93547a567040ac99f04921d4311362512d6095e111185226e`）；此测试只走其中的 `WriteFua`，不走 `WriteVolatile`。

## 轨迹（self-checked）

| 操作 | 文件页轨迹（绝对 4 KiB LBA） | 调用方和回读 |
| --- | --- | --- |
| 首写页 0 为 A | `59491323 FUA_OK` → `59491259 FUA_OK`（present） | 成功 |
| 页 0 覆写为 B | 仅 `59491323 FUA_OK` | 新进程重开读到 B |
| 最后一页 | `61588474 FUA_OK` → `59491322 FUA_OK` | 新进程读回；头页在 `59491258`，两侧窗外哨兵不变；跨窗请求未提交 |
| 未 present 页的数据写故障 | `59524092 FUA_ERROR`，无 bitmap 写 | completion `kIOReturnIOError / 0 B`；重开不 present |
| 同页的 bitmap 写故障 | `59524092 FUA_OK` → `59491260 FUA_ERROR` | completion `kIOReturnIOError / 0 B`；重开不 present，读取 seed 而不是未提交的文件数据 |
| 短写 / 同步失败 / 超时 | `59524093 SHORT` / `59524094 SYNC_UNKNOWN` / `59524095 TIMEOUT_UNKNOWN`，均无 bitmap 提交 | 均 `kIOReturnIOError / 0 B`；前两项 `FATAL_QUARANTINED`，第三项 `TIMEOUT_ORPHAN`；`doSynchronize` 返回 `kIOReturnIOError`，store sync 和重试拒绝，重开回 seed。数据和 bitmap 既有故障也覆盖 `doSynchronize`。 |
| FUA 未证明或打开后失去证明 | 零写提交 | `Provider` 拒绝打开或写入，且拒绝 sync；已打开时，故障写入前 `doSynchronize` 已返回 `kIOReturnIOError`；健康 v1 句柄返回成功。 |
| 普通打开 v3 输入 | 普通 v3、v1 合法头碰撞、不同 seed 的 disposable v3、次锚点撕裂，四例均在与双 GPT 相同的锁会话内拒绝发布；直接调用 `native_ufs_store_write` 也失败，零写提交。锚点 I/O 失败及 v1 请求保留块数也拒绝。 | 四个稀疏镜像各 17,183,031,296 逻辑字节逐字节不变。 |
| 固定工作集 | 257 页先填充，再做 54 轮共 13,878 页次覆写；每次仅一笔 data-slot FUA，无日志/bitmap 写 | 新进程重开逐字节验证最终 257 页 |

## 复跑

WSL Linux，临时目录使用支持 `SEEK_DATA/SEEK_HOLE` 的稀疏文件系统；测试用 ASan/UBSan，按场景启动新进程。

```sh
python3.11 -B tests/test-nuwa-v1-entry.py ../../UniXNU \
  ../worktree-dualbank/out/nuwa-dualbank-20261126-build/nuwa-data-provider/NativeUfs.cpp \
  out/nuwa-no-glyph-20261128-build/nuwa-data-provider/CombinedRead.h
python3.11 -B tests/test-nuwa-retained-entry.py out/nuwa-no-glyph-20261128-build ../../UniXNU \
  --output out/nuwa-v1-retained-regression-20261128 --disposable
for f in dualbank data-write; do
  c++ -std=c++17 -Wall -Wextra -Werror -fsanitize=address,undefined \
    -fno-sanitize-recover=all -no-pie -pthread "tests/test-nuwa-$f.cpp" -o "out/test-nuwa-$f-v1-review"
  "out/test-nuwa-$f-v1-review"
done
```

本轮原始输出：`out/nuwa-v1-entry-20261128.log`、`out/nuwa-v1-retained-regression-20261128.log`、`out/nuwa-v1-dualbank-regression-20261128.log`、`out/nuwa-v1-data-write-regression-20261128.log`。独立 verifier 未复跑。
